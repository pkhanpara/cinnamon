# Holdings view (live prices, account checkboxes)

## Why
The core feature: see holdings across all accounts or a ticked subset, with live prices.

## Pre-flight findings
- `git push`: `c72b8aa..61d5f7b main -> main` (CSV import).
- Design questions asked first. User chose live Finnhub prices NOW (I had recommended file values first),
  merged rows expandable per account, selection remembered per browser, and all four extras including the
  donut (I had suggested deferring it: built as inline SVG, no new dependency).
- Live Finnhub probes: header auth `X-Finnhub-Token` works; unauthenticated call returns an error body;
  unknown symbol `ZZZZNOPE` -> `{"c":0,...,"t":0}` with HTTP 200; `BRK.B`/`BRK-B` and `BF.B`/`BF-B` both resolve;
  `x-ratelimit-limit: 60`, `x-ratelimit-remaining: 53` after a few calls.

## Design
See ADR 0003. Rejected: `?token=` auth (key in logs/URLs), caching per user (public data), summing partial
lines into a row value (misleading), counting unpriced cost basis in gain (huge fake losses), server-side
selection storage, a chart library for one donut.

## What was done
- Backend: `providers/{base,finnhub,__init__}.py`, `quotes.py` (TTL cache + stale fallback), `holdings.py`
  (pure Decimal aggregation), `api/holdings.py`, `QuoteCache` model, settings `finnhub_base_url`,
  `quote_ttl_seconds`; `httpx` moved to runtime deps.
- Alembic autogenerate emitted `app.db_types.DecimalText()` with no import AGAIN (same flaw as the import
  migration). Fixed the root cause with a `render_item` hook in `migrations/env.py` that renders it as
  `sa.Text()`; regenerated `9992e2b4882f_quote_cache`; `alembic check`: no drift.
- Test safety: the `client` fixture forces the quote provider to `None` so no test can reach the real
  Finnhub with the dev `.env` key.
- Mutation checks (all restored afterwards):
  - gain over all cost basis -> caught; no ownership check in holdings -> caught; empty ids = all -> caught.
  - **Key in the URL instead of the header SURVIVED** (111 passed) because my test built its own
    `httpx.Client` with the header, bypassing the real constructor. Fixed: `FinnhubProvider` now takes a
    `transport` and always builds its own client; re-ran the mutation -> `test_key_goes_in_a_header_never_in_the_url` fails.
    The mutation had been applied to an uncommitted file, so `git checkout` could not undo it; I restored it by hand.
  - Frontend: removing the stale-response guard, null-sorts-first, and "none selected still requests" -> all caught.
- Frontend: `HoldingsService`, `core/account-selection.ts` (+spec), `core/donut.ts` (+spec), `app-donut`,
  `pages/holdings`, route + nav, landing page changed from `/accounts` to `/holdings` (login, setup, guards
  and their specs updated).
- Tests: 111 backend (provider via MockTransport incl. 429/401/garbage/network error, cache TTL/stale,
  14 hand-checked math cases, 16 API cases); 67 frontend.
- Real E2E (fresh DB, real Finnhub, real-derived seed + a small Roth account holding NVDA and VOO):
  - API: 20 holdings, all live; total `691573.93`, cost `412630.85`, day `+1399.57 (+0.2028%)`, weights sum 100.0.
    Cross-checks vs the PDF: Robinhood+M1 value equals the PDF's 685,600.54; Roth adds about 5,973.40;
    PDF day change was +0.20%. NVDA merged across two accounts (917.239 + 10 = 927.239 shares).
  - Browser: lands on `/holdings`; tiles, donut and table render; row gains match the PDF within a cent or two
    (TSM -678.08 vs -678.09); expanding NVDA lists both accounts; unticking M1 and Roth -> total `526,422.79`,
    cost `289,758.49`, URL `?accounts=1`; reload keeps the selection; `?accounts=2,3` overrides it; Symbol sort works.
  - Backend/dev-server logs contain 0 occurrences of the API key; two API calls inside the TTL returned the same `prices_as_of`.
  - Outage: bad key + empty cache -> warning `Finnhub rejected the API key`, 18 rows on imported values,
    NVDA and VOO unpriced (Roth file has no market_value) and excluded from totals; bad key not in logs.
