# Seed overlap: split holdings across accounts

## Why
`scripts/make_seed.py` routed ETFs to `m1` and everything else to `robinhood`, so no symbol was in
two accounts and the merged-row UI (Home expand control, ticker-page per-account lines) was never
exercised with real-shaped data. Pre-change seed: robinhood 17 rows / 526,422.80, m1 3 rows /
159,177.74, total 685,600.54 (equals the sum in `seed/private/holdings.json`).

## Pre-flight findings
- Quantity is derived as `market_value / live price`, so a split has to divide quantity too.
- `SnapshotConnector` rejects `quantity <= 0` and duplicate symbols per file, so every leg must be
  positive and a symbol appears once per account (`backend/app/connectors/snapshot.py`).
- Committed tests use `seed/sample/`, not `seed/private/`, so tests cannot depend on the private data.
- Working tree was shared with two other agents (news refresh, LLM chat) and already dirty on `main`:
  no branch switch, no commit; edited only TODO.md lines for this item.

## Design
- `SPLITS` table (symbol -> [(account, fraction)]); NVDA 60/40 robinhood/m1, MSFT 50/30/20
  robinhood/m1/schwab, VOO 50/50 m1/robinhood, AAPL 70/30 robinhood/schwab.
- Pure `build_rows(holdings, price_of, as_of, splits)` with injected price function; `main()` does
  key, quotes and file IO only. All Decimal. `split_amount` gives the last leg the remainder, so
  quantity (4dp), cost basis and value (cents) sum exactly.
- Validation before any write: unknown symbol, fractions not > 0 / not summing to 1, duplicate or
  unknown account, non-positive leg, duplicate symbol per file, per-symbol sums vs holdings.json.
- Rejected: hand-editing the CSVs (not reproducible), hash-based random splits (not deterministic),
  splitting at import time (would change the product for a test-data need), two accounts only (no
  3-line case).

## What was done
- `backend/tests/test_make_seed.py`: 16 tests (fabricated holdings, fake prices).
- Mutation checks (one at a time, reverted): remainder dropped (8 fail), fractions sum 1.1 (6),
  unsplit ETF misrouted (1), quantity guard removed (1), duplicate guards removed (1 and 2).
  Two survived at first: float arithmetic and removing NVDA from `SPLITS`; added
  `test_split_rounds_half_up_in_decimal_not_float` and `test_configured_overlap_covers_the_todo_requirements`;
  both now killed.
- `uv run pytest`: 238 passed (includes the other agents' in-progress tests).
- `python3 scripts/make_seed.py` printed: robinhood 18 rows 434,756.12; m1 5 rows 237,451.58;
  schwab 2 rows 13,392.84; grand total 685,600.54. `git check-ignore` confirms `seed/private/` ignored.
- Isolated stack (uvicorn :8330 with a scratch DB, `ng serve` :4330 via a custom proxy config, no
  Finnhub key): created 3 accounts, imported the 3 files. `/api/holdings`: 20 merged rows, total
  685,600.54, cost basis 409,630.85; NVDA 2 lines, MSFT 3, VOO 2, AAPL 2. Playwright drove Home
  (expand all four, uncheck schwab: MSFT keeps an expand control with 2 lines) and `/symbol/MSFT`.

## Gotchas
- `pkill -f` with a pattern that appears in the command itself kills the invoking shell; stop dev
  servers by port instead.
- With a live Finnhub key per-line value is `qty x price` rounded per line, so totals can differ
  from the PDF by cents; the exact check needs no key.
- Old seed CSVs backed up to the session scratchpad before regeneration; `schwab_positions.csv`
  is new and is not removed if `SPLITS` stops using it.
