# Pin uv image, fix image build, verify Docker with auth + UI + yfinance

## Why
- `Dockerfile` used `ghcr.io/astral-sh/uv:latest` (unreproducible builds).
- The only existing image (`cinnamon:dev`, 228MB) predated yfinance/pandas, auth and the ticker page.

## Pre-flight findings
- `docker build` **failed before any of my changes mattered**: `npm ci` in `node:22-slim` (npm 10.9.9) -> `Missing: @emnapi/core@1.11.3 from lock file` (also `@emnapi/runtime`). `node:24-slim` (npm 11.19) failed the same way, so it is the lockfile, not the Node version. Local npm 11.6.2 accepts the lock, which hid it.
- Fix: regenerate under the image's npm: `docker run -v <copy>:/w node:22-slim npm install --package-lock-only --ignore-scripts`, copy back `frontend/package-lock.json` (+25/-25 lines: adds the two optional `@emnapi` entries, drops stale `"peer": true`). `npm ci --dry-run` passes under npm 10 and the local npm 11.
- uv: `ghcr.io/astral-sh/uv:latest` == 0.12.23, index digest `sha256:61d393e4...5b21` (same as the `0.12.23` tag, checked with `docker buildx imagetools inspect`).

## Design
- Pin `uv:0.12.23@sha256:<index digest>` (tag for humans, digest for reproducibility). Bump both together.
- Move `uv sync` into a `deps` stage and copy only `/app/.venv` into the runtime stage (same `/app` path, same base image), so the 54MB uv binary no longer ships. Rejected: keeping uv in the runtime image (nothing uses it at run time; `which uv` -> absent now).
- compose: `${CINNAMON_PORT:-8000}` and `${CINNAMON_IMAGE:-cinnamon:dev}` so parallel runs/other worktrees don't collide; defaults unchanged.
- `.dockerignore`: added `backend/tests`, `backend/static`, pytest/ruff caches.

## What was done / results
- `docker compose -p cinnamon-pinuv build --no-cache`: image 383MB with uv in runtime (venv layer 208MB vs 53.6MB before: pandas, numpy, lxml, curl-cffi), **328MB** after the `deps` stage split (baseline 228MB). Cached rebuild: 14 CACHED steps.
- Ran on port 8410, throwaway project/volume: `/api/health` ok, `/` and `/holdings` 200 (SPA), `/api/nope` 404, uid 10001, `/app/data` writable, container `healthy`, no error lines in logs.
- In container: `yfinance 1.7.0, pandas 3.0.6, numpy 2.5.3`, `curl_cffi` import ok.
- Auth flow via curl: default admin login -> `must_change_password: true`, `/accounts` 403 "Password change required" -> change-password -> accounts 200 -> create account -> preview + commit `seed/sample/robinhood_positions.csv` (3 rows) -> `/api/holdings` total_value 19673.15 with live_count 3 (Finnhub key from `.env`) -> `/api/symbols/AAPL/history?range=1m` returned bars (yfinance works in container).
- reset-password: `exec -T` with stdin ok, `run --rm -T` ok (old passwords 401, newest 200, `must_change_password` true), unknown user -> `error: No such user`, exit 1, short password -> exit 1. Data and login survived `docker compose restart`.
- `uv run pytest` 287 passed; `ruff check` clean. Cleaned up: `down -v`, image removed.

## Gotchas
- Local `npm ci` success does not imply `node:22-slim` `npm ci` success.
- zsh: `$P` holding `docker compose -p x` does not word-split; use a function.
- Files: Dockerfile, docker-compose.yml, .dockerignore, frontend/package-lock.json.
