# Admin Users page

## Why
Multi-user was only reachable through the API: no way in the UI to create a second user.

## Pre-flight findings
- `git push`: `3a96f3d..8cec49c main -> main` (previous UI commit).
- Backend already exposes `GET/POST /api/users`, `PATCH /api/users/{id}` with self-lockout protection (ADR 0004).
- The "not done" items from the last summary (Users page, in-app delete dialog, Docker rebuild) were already in TODO.md.

## Design
- `UsersService`, `adminGuard` (signed out -> /login, non-admin -> /accounts), lazy `Users` page, header nav
  (`Accounts`, `Users` for admins only).
- UI hides Make admin / Deactivate on your own row (backend returns 400 anyway); Reset password stays available.
- Client-side min length 10 for passwords mirrors the backend; server messages still shown via `apiError`.
- Rejected: hiding the route only in the nav. The guard and the API both enforce admin-only.
- Not built: deleting users (backend has no endpoint; TODO).

## What was done
- `ng test`: 28 passed (adminGuard x3, Users page x6 added) and `ng build` clean.
- Real-browser E2E with two named agent-browser sessions on a fresh SQLite DB:
  - admin setup -> nav shows `Accounts`, `Users`; own row shows only `Reset password`.
  - created user typed as `Alice` -> stored/displayed as `alice`; "Created alice." notice.
  - alice signed in: nav has only `Accounts`; `/users` -> redirected to `/accounts`; `fetch('/api/users')` -> 403.
  - admin Deactivate while alice was on a page: alice's next Add-account POST -> 401 -> interceptor -> `/login`;
    signing in again -> "Invalid username or password"; Activate -> alice signed in -> `/accounts`.
  - admin Reset password: "Password reset for alice. Their sessions were signed out."; alice's old session
    `fetch('/api/auth/me')` -> 401. (Login with the new password is covered by backend test
    `test_password_reset_kills_sessions`, not re-checked in the browser.)
