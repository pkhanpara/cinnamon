# CSV import phase

## Why
Phase 3: get holdings into the app. No broker API is available, so import files (ADR 0002).

## Pre-flight findings
- `git push`: `8cec49c..c72b8aa main -> main` (Users page).
- Design questions asked up front; user chose: replace-and-discard on re-import, preview then confirm,
  connector chosen by account platform with a generic `snapshot` connector, store the file's values with live
  prices overlaid later. Consequence recorded in ADR 0002: imports are not history for the performance chart.
- `alembic revision --autogenerate` first failed: `Target database is not up to date` (dev DB not at head);
  regenerated against a throwaway DB.

## Design
See ADR 0002. Rejected: stateful server-side preview tokens (temp storage, expiry), merge/upsert by symbol
(sold positions never disappear), Numeric columns (float on SQLite), auto-detecting format from headers.

## What was done
- Backend: `connectors/{base,snapshot,__init__}.py`, `db_types.DecimalText`, models `Import`/`Position`,
  `api/imports.py` (connectors, positions, preview, commit), `AccountOut` gained `position_count`/`last_import_at`,
  `get_owned_account` moved to `api/deps.py`, dependency `python-multipart`.
- Migration `72ae4f6e3168_imports_and_positions`. Autogenerate emitted `app.db_types.DecimalText()` with no import
  (ruff F821 caught it; `alembic upgrade` would have raised NameError). Replaced with `sa.Text()`: migrations
  should not depend on app code. `alembic check` -> "No new upgrade operations detected."
- Tests: 61 backend (parser edge cases incl. NaN/Infinity, formula-looking symbols, duplicate symbols, BOM,
  row limit; API: preview writes nothing, replace semantics, identical-file warning, 413, other user's account
  = 404 on every endpoint, cascade delete, atomicity). Mutation check: inserting `db.commit()` right after the
  delete made `test_database_failure_mid_import_keeps_old_positions` fail (`assert [] == ['DIS','INTC','ORCL']`),
  so the atomicity test is real. Reverted.
- Frontend: `ImportsService`, `pages/import`, accounts list shows "N position(s), imported <date>" + Import link;
  38 tests. First test run hid a TS error behind my `grep` (`flush(unknown)` not assignable), fixed. One failing
  assertion was mine: `FormData.append(name, file, filename)` wraps the file, so identity can't match; compare name/size.
- Real-browser E2E (fresh DB, real-derived `seed/private/*.csv`): preview of the 17-row file showed
  `cost basis 289,758.49 · market value 526,422.80` (= PDF totals minus the 3 ETFs); imported; account list showed
  `17 position(s)`; identical re-import warned "replace ... 17 current position(s)" and "identical to the last import";
  a bad file listed `Line 3 Invalid symbol 'BAD SYM'`, `Line 4 quantity is not a number: 'abc'`,
  `Line 5 Duplicate symbol KO (first on line 2)` with confirm disabled and old data untouched (no BAD symbol);
  M1 import (3 rows). Combined via API: `3+17 positions; mv=685600.54 cost=409630.85`, exactly the PDF's
  `685,600.54` / `409,630.85`.
- Cleaned up temp DB and screenshots (contained real-derived numbers).
