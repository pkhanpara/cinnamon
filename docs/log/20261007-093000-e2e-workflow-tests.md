# End-to-end workflow tests (Playwright)

Status: done. 15 tests green, 3 consecutive full runs (24s / 9s / 9s); `returning-user` also green alone (5 passed, 11.5s).

## Why
Unit specs (vitest) and backend pytest cover pieces, but nothing exercised the real stack as a user does. The default-admin work (commits a817131, 4d6b589) had already shipped one bug that only a true first run exposes: `/auth/setup` returned 500 on a fresh DB because migrations had not run (log `20261007-084500-fix-setup-500-auto-migrate.md`). Request: end-to-end workflow tests, e.g. the first-time login workflow.

## Design
- `playwright.config.ts` boots a throwaway stack on its own ports (backend 8310, `ng serve` 4310, so a running dev server is untouched). Backend is plain `uvicorn app.main:app` on an empty SQLite in `/tmp/cinnamon-e2e` (wiped each run) — the same path as a real first start, no manual migration. `FINNHUB_API_KEY=''` so runs are offline/deterministic. `workers: 1`, serial.
- `e2e/first-login.spec.ts` (10 tests): anonymous -> /login, `/setup` gone; wrong password; default admin forced to change password; app unreachable via UI *and* API (403 `Password change required`) until changed; bad changes rejected; valid change -> Home; old password dead; account + CSV import + holdings; admin creates a non-admin user with isolated data; final **audit** test that fails on any pageerror, console error/warning, unexpected 4xx/5xx (allow-list with reasons), or error text in backend/dev-server logs, and asserts the admin was seeded exactly once.
- `e2e/returning-user.spec.ts` (5 tests): session survives reload/deep link; second import replaces the first; delete account removes holdings; password change signs out other devices (second browser context gets 401); sign out ends the session.
- `e2e/support.ts`: `adminSession()` signs the API in as admin whatever the DB state (fresh -> default password + change; or already changed), so the second spec does not depend on the first.
- Rejected: reset the DB between specs (slower, needs a test-only reset endpoint in the backend); one giant spec file (poor failure localisation); mocking the API with `page.route` (would not have caught the migrations bug).

## Gotchas
- E2E state lives in `/tmp/cinnamon-e2e` (db, `backend.log`, `frontend.log`, traces in `results/`); deleted at the start of every run.
- The audit test greps the logs, so any new log noise at ERROR level fails the suite.
- Ports 8310/4310 must be free (`reuseExistingServer: false`).
- Specs run alphabetically; `first-login` must keep sorting before anything that assumes a changed admin password only if it skips `adminSession()`.
