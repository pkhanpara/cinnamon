# Auth backend: users, sessions, accounts

## Why
Phase 2 of the plan. Multi-user app: every later feature (holdings, imports) needs an
authenticated user and per-user account scoping first.

## Pre-flight findings
- `git push` of 391e830 succeeded (`9028cd0..391e830 main -> main`).
- No migrations existed (`backend/migrations/versions` empty), `alembic upgrade head` was a no-op.

## Design
See ADR 0004. Rejected: JWT (revocation), storing raw session tokens (DB leak = account takeover),
403 for foreign rows (leaks id existence), free-form platform string vs. connector registry
(registry doesn't exist yet; slug-pattern validation for now).

## What was done
- `uv add argon2-cffi`; added `models.py`, `security.py`, `schemas.py`, `api/{deps,auth,users,accounts}.py`;
  settings gained `session_cookie_name`, `session_days`, `cookie_secure`.
- Alembic `env.py` imports `app.models`; `alembic revision --autogenerate` -> `9f4631c79302_users_sessions_accounts`.
- Tests: 19 in `tests/test_auth.py`, `tests/test_accounts.py` (temp in-memory SQLite per test).
  First run: `2 failed, 17 passed`.
  Root cause: pydantic applies `StringConstraints(pattern=...)` BEFORE `to_lower`, so `Alice`/`Robinhood`
  returned 422. Fixed with a `BeforeValidator` that strips+lowercases first. Then `19 passed`, ruff clean.
- Real-migration smoke on a temp DB: `Running upgrade -> 9f4631c79302`; tables
  `['accounts','alembic_version','sessions','users']`; via curl: setup -> create account -> list ->
  anonymous `/api/accounts` = 401.

## Gotchas
- My first smoke script was invalid: zsh aborted on an unmatched `rm -f file*` glob, so migrations never
  ran and every call returned 500. That was the script, not the app. Reran without globs.
- Tests that mutate session expiry reach into `app.dependency_overrides[get_db]` directly.
- SQLite returns naive datetimes; `current_user` re-attaches UTC when comparing expiry, and `created_at`
  in API output has no timezone suffix.
